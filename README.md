# Бронирование переговорной

Интерфейс бронирования переговорной комнаты на рабочий день (09:00–18:00): выбор даты, таймлайн броней,
создание, редактирование и удаление с валидацией бизнес-правил на клиенте и на сервере (mock API).

**Demo:** _ссылка появится после деплоя_ · **Время:** ~2 часа работы с AI (по логу сессии, `docs/ai-chat.md`) + уточнения у рекрутера

> **Важно для проверки.** Mock-сервер намеренно отвечает `409` примерно на каждое пятое создание брони —
> так демонстрируется обработка конфликта из п.8 ТЗ («время занял другой пользователь»). Это не баг:
> выберите другое время и сохраните. На демо (Vercel) данные хранятся в памяти отдельных копий сервера
> и могут «пропадать» между запросами. Подробности — на странице «Как это работает» (`/about`).

## Запуск

```bash
npm install
cp .env.example .env   # необязательно
npm run dev            # http://localhost:3000
```

| Команда | Что делает |
|---|---|
| `npm test` | unit-тесты бизнес-правил (vitest) |
| `npm run e2e` | e2e (Playwright): сборка + сценарии на десктопе и мобильном |
| `npm run lint:all` | ESLint, tsc, steiger + fsd-check (архитектура FSD), проверка Tailwind-классов |
| `npm run build` | production-сборка |

Переменные (`.env.example`): `NEXT_PUBLIC_API_BASE_URL` — адрес API (по умолчанию встроенный mock `/api`),
`MOCK_LATENCY_MS` — задержка ответов mock, `MOCK_CONFLICT_RATE` — доля POST, на которые mock отвечает `409`
(имитация «слот занял другой пользователь»). `MOCK_CONFLICT_RATE=1` — конфликт на каждое создание.

## Деплой (Vercel)

```bash
npx vercel          # первый раз: логин и привязка проекта, дальше — preview
npx vercel --prod   # продакшен; ссылку вписать в начало README
```

Переменные окружения не обязательны: по умолчанию используется встроенный mock API.

## Стек и структура

Next.js 16 (App Router, Route Handlers как mock API) · TypeScript · Tailwind 4 · shadcn/ui · TanStack Query ·
axios · zod · react-hook-form · zustand · next-intl (RU/EN). Архитектура — Feature-Sliced Design:

- `src/entities/booking` — схемы, запросы, query-хуки и **бизнес-правила** (одна функция для формы и сервера);
- `src/_pages/booking` — экран: таймлайн дня, форма, диалоги;
- `src/_app/api-routes` — mock-бэкенд (in-memory), `app/api/*` — только ре-экспорты;
- `src/shared` — http-клиент, обработка ошибок, работа со временем, UI-кит.

Сетевой слой отделён: UI → хуки → `entities/booking/api` → axios. Переход на реальный API —
смена `NEXT_PUBLIC_API_BASE_URL`.

## Что сделано

- Все пункты ТЗ: выбор даты, просмотр, создание/редактирование (включая перенос на другую дату)/удаление, правила 1–8.
- Страница «Как это работает» (`/about`): правила, как проверить конфликт, API.
- Состояния: скелетон загрузки, пустой день, ошибка с «Повторить», отправка формы.
- Конфликт `409`: сообщение в форме, список броней перезапрашивается, введённые данные сохраняются.
- Адаптив от 360px, клавиатурная навигация, aria-подписи.
- Удобство: дата в URL, выделение интервала мышью, занятое время недоступно в форме, сводка дня,
  горячие клавиши (← → T N), переключатель темы, предзагрузка соседних дней без мигания.
- Интерфейс на русском и английском (переключатель в шапке), сервер отвечает на языке интерфейса.
- Тесты: unit (правила, расчёт сетки) и e2e (Playwright, включая обработку 409).
- Переписка с AI — [docs/ai-chat.md](docs/ai-chat.md).

## Допущения (согласованы с рекрутером)

- Бронирование только по будням (пн–пт), праздники не учитываются.
- «Сейчас» — по часовому поясу браузера (передаётся серверу в `X-Time-Zone`); время брони хранится без пояса.
- Сегодня бронь начинается с ближайшего будущего времени по сетке 15 минут.
- Начавшиеся и прошедшие брони нельзя изменить или удалить.
- Авторизации нет — любой пользователь управляет любой бронью.

## Что не сделано / что дальше

- Хранилище in-memory: сбрасывается при рестарте и не общее между serverless-инстансами на Vercel.
- Нет оптимистичных обновлений — список перечитывается после каждой мутации.
