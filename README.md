# Бронирование переговорной

Тестовое задание Frontend Engineer для **Mad Devs**: интерфейс бронирования переговорной комнаты на рабочий
день 09:00–18:00 — выбор даты, таймлайн броней, создание, редактирование и удаление с проверкой бизнес-правил
в форме и на сервере (mock API).

- **Демо:** https://maddevs-tz.vercel.app
- **Автор:** Telegram [@a_diyar_tr](https://t.me/a_diyar_tr)
- **Репозиторий:** https://github.com/WebDiyar/maddevs_tz
- **Подробный разбор ТЗ, ответов рекрутера и решений:** страница «Как это работает» (`/about`)
- **Переписка с AI:** [docs/ai-chat.md](docs/ai-chat.md)
- **Время:** около 4 часов работы с AI плюс уточнения у рекрутера (таймбокс 4–6 ч)

> **Важно для проверки.** Mock-сервер намеренно отвечает `409` примерно на каждое пятое создание брони —
> так показывается обработка конфликта из п.8 ТЗ («время занял другой пользователь»). Это не баг:
> выберите другое время и сохраните. На демо данные хранятся в памяти отдельных копий сервера Vercel
> и иногда могут «пропадать» между запросами.

## Запуск

```bash
npm install
cp .env.example .env   # необязательно
npm run dev            # http://localhost:3000
```

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер |
| `npm test` | unit-тесты (vitest): бизнес-правила, расчёт сетки, время |
| `npm run e2e` | e2e (Playwright): собирает прод, сценарии на десктопе и мобильном, проверка доступности axe |
| `npm run lint:all` | ESLint, tsc, steiger + fsd-check (архитектура FSD), проверка Tailwind-классов |
| `npm run build` | production-сборка |

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `NEXT_PUBLIC_API_BASE_URL` | `/api` | адрес API: встроенный mock или реальный бэкенд |
| `MOCK_CONFLICT_RATE` | `0.2` | доля созданий, на которые mock отвечает `409`: `0.2` или `20` (%), `0` — никогда |
| `MOCK_LATENCY_MS` | `400` | задержка ответов mock, чтобы были видны состояния загрузки |

## Деплой (Vercel)

Vercel → **Add New → Project → Import** репозитория → **Deploy**. Настройки определяются автоматически,
секреты не нужны. Переменные выше — по желанию (Project → Settings → Environment Variables, затем Redeploy).

## Что сделано

**Требования ТЗ**
- Выбор даты, просмотр броней дня, выбор начала и окончания, создание, редактирование, удаление.
- Все 8 бизнес-правил: рабочий день, start < end, 30 мин – 2 ч, без пересечений (касание допустимо), нельзя
  в прошлое, бронь не конфликтует сама с собой, обработка серверного `409`.
- Правила — одна функция для формы и mock-сервера; сервер валидирует всё сам.
- Состояния: загрузка (скелетон), пусто, ошибка с «Повторить», отправка формы.
- Ошибки сервера 400 / 404 / 409 / 422 и отсутствие сети — понятные сообщения.
- `409`: сообщение в форме, список перезапрашивается, введённые данные сохраняются.
- Сетевой слой отделён от UI: UI → хуки → `entities/booking/api` → axios.
- Адаптив от 320 до 2560 px и базовая доступность.

**По ответам рекрутера**
- Только будни (пн–пт); праздники не учитываются.
- «Сейчас» — по часовому поясу браузера (передаётся серверу в `X-Time-Zone`).
- Сегодня начало — с ближайшего будущего шага 15 минут; шаг 15 минут проверяет и сервер.
- Начавшиеся и прошедшие брони нельзя изменить или удалить.
- При редактировании меняется всё, включая дату.

**Сверх ТЗ**
- Страница `/about` с полным разбором; своя страница 404.
- Интерфейс и ответы сервера на русском и английском; светлая и тёмная тема.
- Дата в URL, выделение интервала мышью, занятое время недоступно в форме, сводка дня,
  горячие клавиши (← → T N), предзагрузка соседних дней без мигания.
- Раскладка: телефон — одна колонка; планшет — навигация и кнопка в строку; ноутбук и шире — календарь месяца
  и сводка слева, таймлайн справа; монитор — плавное масштабирование.
- Тесты: 22 unit, 19 e2e (включая axe WCAG 2 AA).

## Стек и архитектура

Next.js 16 (App Router, Route Handlers как mock API) · React 19 · TypeScript · Tailwind CSS 4 · shadcn/ui ·
TanStack Query · axios · zod · react-hook-form · zustand · date-fns · next-intl · vitest · Playwright.

Feature-Sliced Design:

- `app/` — роутер Next.js, только ре-экспорты;
- `src/_app` — провайдеры, шапка, стили, mock API (`api-routes`), сборка переводов;
- `src/_pages` — экраны `booking`, `about`, `not-found`;
- `src/entities/booking` — схемы, запросы, query-хуки и **бизнес-правила**;
- `src/shared` — http-клиент, обработка ошибок, работа со временем, UI-кит (shadcn).

## Допущения

- Авторизации нет (ТЗ: не нужна) — любой пользователь управляет любой бронью.
- Время брони хранится без пояса (`HH:mm`) — все пользователи в одном офисе.
- Название брони необязательно, до 80 символов; горизонт бронирования не ограничен.
- Сохранение ждёт ответа сервера, удаление — через подтверждение.

## Что не сделано / что дальше

- Хранилище в памяти: сбрасывается при перезапуске и не общее между копиями сервера на Vercel → Redis или БД.
- Нет оптимистичных обновлений — бронь появляется после ответа сервера (~0,4 с).
- Нет CI — следующий шаг: GitHub Actions с `lint:all`, unit и e2e.
